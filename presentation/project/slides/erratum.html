FINDING 1

A one-character slip in Algorithm 1

After a YES at the median radius, the printed pseudocode discards every candidate ≤ 2r — including the median that just passed.

line 23 (printed):  X ← X \ { e | e ≤ 2r }

fix:                X ← X \ { e | e < 2r }

The paper’s prose already describes the correct rule (“remove all elements smaller than 2r”). With it, Algorithm 1 was correct on every test.

59%

of 8,967 random runs return a wrong value when the pseudocode is followed literally (5,288 runs; 1,478 end with no candidate left)

[Name 2] · Part 2

Algorithm 1 is the outer binary search over candidate distances. When the decision says YES at the median, the printed line 23 removes all candidates less than or equal to that median, so the feasible median itself is thrown away. Followed literally, the search returns a wrong value in 59 percent of our random runs. The text of the paper describes the correct rule, so this is a typo, and the fix is one character: less-or-equal becomes strictly less. We mention it because anyone implementing from the pseudocode would hit it. (Tip: present this respectfully, as a verification result; it is worth sharing with the authors.)
