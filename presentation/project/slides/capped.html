OUR ALGORITHM

The capped dynamic program

1

One table entry per chord

The value of a chord depends on the angle allowed by the triangle on its other side, as a step function.

2

Keep only the first k − 2 steps

A decision only asks “do k points fit?”, so each chord stores k − 2 apex points instead of a full table.

3

Binary search inside a window

A farthest-first greedy value g gives g ≤ r* ≤ min(2g, perimeter / k); only candidates inside are tested.

Original DP

O(n⁴ k²)

Ours, optimisation

O(n³ log k log n)

Ours, one decision · memory

O(n³ log k) · O(n²k)

[Name 1] · Part 1

Three ideas. First, instead of a state for every chord AND every apex (that is what costs n^4), we give each chord a step function of the angle constraint imposed by its parent triangle. Second, capping: we only need to know whether k points fit, so each chord remembers just k−2 thresholds, each stored as the apex point that attains it; comparing them is an in-circle test, and finding how many pass is a binary search, hence the log k. Third, a search window from the farthest-first greedy and the hull perimeter shrinks the binary search. Result: O(n^3 log k log n) versus O(n^4 k^2); memory O(n^2 k).
