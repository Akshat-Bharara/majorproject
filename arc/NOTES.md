# k-dispersion in convex position under the arc property

Implementation and validation notes. The polished write-up is Section 7 of
`../paper/paper.pdf`; result tables are in `results/tables.md` (generated by
`make_tables.py` from the raw outputs in `results/`).

## 1. Setting

`P = (p_0, ..., p_{n-1})`: strictly convex, counterclockwise (ccw), integer
coordinates, indices mod n. All comparisons are on squared distances
(`|qx| >= r` is inclusive); no floating point is used in any decision
(floating point appears only inside instance *generators*, whose output is
then verified exactly).

* `Far_r(q) = { x != q : |qx| >= r }`; `a(q)` / `b(q)`: first point of
  `Far_r(q)` in ccw / cw order.
* **r-arc property**: for every q, `Far_r(q)` is a run of consecutive points in
  the order `p_{q+1}, ..., p_{q-1}`.
* **Unimodal**: for every q, `|p_q p_{q+t}|`, `t = 1..n-1`, is strictly
  increasing, then strictly decreasing, *where the maximum may be attained at
  two consecutive t* (see Deviation D1).

## 2. Statements and proofs

**Lemma A1 (exchange).** Assume the r-arc property. Let S be r-far and let
s, s' be consecutive in S (ccw). Then `(S \ {s'}) ∪ {a(s)}` is r-far.

*Proof.* s' is far from s, so a(s) lies on the ccw arc (s, s'], and
`|s a(s)| >= r`. Let t ∈ S \ {s, s'}. `Far(t)` is a run in the linear order
`t+1, ..., t-1` and contains s and s'. The ccw arc [s, s'] does not contain t
(s, s' are consecutive in S), so its points lie between s and s' in that
linear order and therefore belong to `Far(t)`. Hence `|t a(s)| >= r`. ∎

The proof was checked and is correct. Note that it uses the arc shape of
`Far(t)` only for the points t of the *current* set.

**Theorem A2.** Assume the r-arc property, k >= 2. Call the chain
`x_0 = q, x_{i+1} = a(x_i)` (i < k-1) *proper* if every a(x_i) is defined and
the unwrapped ccw offsets from q are < n.

1. If S is an r-far k-set and q ∈ S, the chain of q is proper and r-far.
2. A proper chain is r-far iff `|x_0 x_{k-1}| >= r`.

So an r-far k-set exists iff some q has a proper chain with
`|x_0 x_{k-1}| >= r`.

*Proof.* (1) S = {s_1 = q, ..., s_k} ccw. Apply A1 to (x_0, s_2): s_2 is
replaced by x_1. Now (x_1, s_3) is consecutive in the new r-far set; replace
s_3 by x_2; and so on. x_i ∈ (x_{i-1}, s_{i+1}], so the chain is proper.
(2) Fix i. After x_i the other chain points appear in the order
`x_{i+1}, ..., x_{k-1}, x_0, ..., x_{i-1}`. The first is a(x_i) ∈ Far(x_i).
The last is in Far(x_i) too: for i >= 1 because x_i = a(x_{i-1}) (symmetry of
the distance), for i = 0 by assumption. Far(x_i) is contiguous, so it contains
all of them. ∎

**Remark (the chain test of the task statement).** The task's condition (ii)
("for every i the cyclic predecessor of x_i lies in Far(x_i), i.e.
`ccw_offset(x_i -> x_{i-1}) <= ccw_offset(x_i -> b(x_i))`") is correct, but for
i >= 1 it holds automatically by symmetry of the distance. Only i = 0 carries
information: the test is "proper and `|x_0 x_{k-1}| >= r`". Both forms are
implemented (`decide_chain`: the task's form, O(nk); `decide_lift`: the
closing test with `a^{k-1}` by repeated squaring, O(n log k)) and are compared
with each other and with brute force.

**Running times.**

* a(q), b(q): O(n) by scanning; for unimodal P, O(log n) after computing the
  peak of every row by binary search (O(n log n) once).
* Decision D(r): O(n^2) under the arc property; O(n log n) for unimodal P
  (O(n log n) for a(.), O(n log k) for the chains, O(n) memory).
* O1: sort the distinct distances, binary search: O(n^2 log n) time, Θ(n^2)
  memory.
* O2 (unimodal P): each row splits at its peak into an increasing and a
  decreasing list: 2n implicit sorted lists holding every candidate. Keep
  (lo, hi), lo feasible, hi infeasible, and for each list the range of entries
  strictly inside. Each round: pick a uniformly random remaining entry
  (O(n)), run D (O(n log n)), shrink the ranges by binary search
  (O(n log n)). All entries equal to the pivot disappear, and with probability
  >= 1/2 at least a quarter of the entries are removed, so the expected number
  of rounds is O(log n): **expected O(n log^2 n) time, O(n) space**.
* Adaptive mode (general convex P): O1 with scanning, plus an O(n^2) check of
  the arc property at every tested radius; returns `NOT_APPLICABLE` if a check
  fails. O(n^2 log n); exact whenever it answers.

**Unimodality test in O(n log n)** (`unimodal_fast`). For the hull edge
(p_j, p_{j+1}) the points strictly closer to p_j are cut off by the
perpendicular bisector, hence form a cw run p_j, p_{j-1}, ... of length c_j
(binary search); z_j = 1 iff the next point is equidistant. In row q the step
p_{q+t} -> p_{q+t+1} is an increase iff t < c_{q+t}, a tie iff t = c_{q+t} and
z_{q+t} = 1, a decrease otherwise. Row q is not unimodal iff a non-increase is
followed by a non-decrease, i.e. iff for j = q+t:
`c_j <= t` and `t+1 <= c_{j+1} - 1 + z_{j+1}` for some t in [0, n-3]. So
P is unimodal iff `c_j > min(c_{j+1} + z_{j+1} - 2, n - 3)` for all j.
Validated against the O(n^2) definition on every test instance.

## 3. Deviations from the task statement (please read)

**D1. Unimodality must allow a tie at the peak.** With the strict definition
(strictly increasing then strictly decreasing) a regular polygon with an odd
number of vertices is *not* unimodal (the two points opposite to q are
equidistant), and neither are most cocircular lattice sets. On a circle ties
occur only between the two points symmetric about the antipode, so the row is
strictly increasing, then (possibly) one tie, then strictly decreasing. All
algorithms (peak search, a/b search, O2) are correct for this definition, and
it still implies the arc property for every r.

**D2. Unimodal instances with n >= 10^5 do not fit into |coord| <= 2^29 by
rounding.** Exactly cocircular lattice sets inside the box have at most a few
thousand points. Rounded circle points stay strictly convex and unimodal up
to n = 50 000 (verified), but at n = 100 000 rounding destroys convexity
(`results/feasibility.txt`). Convex lattice polygons with 10^6 vertices do
fit (edges = all primitive vectors of norm <= 724), but they are not unimodal
for any size tried. Therefore the runs with n = 10^5 and 10^6 use a circle of
radius 2^60 with `__int128` squared distances (`arc::Wide`); the library is a
template over the distance type, the code path is identical. For n <= 10^4
both modes are reported.

**D3. O1 is only run for n <= 10^4** (Θ(n^2) memory: 5·10^9 distances at
n = 10^5). For n >= 10^5 the result of O2 is validated by (a) an exact
closest-pair computation on the witness (so the reported value is attained)
and (b) the exact unimodality test on the instance (so the theorem applies).

## 4. Failed hypotheses (all re-verified by `check_hypotheses.py`)

Instances are in `data/hypothesis_counterexamples.json`.

* **H1: "arc-shaped far sets only for the points of one r-far k-set suffice."**
  True for k = 3 (the proof of A2 then only uses points of S). **False for
  k = 6**: a 10-point set has an r-far 6-set all of whose points have
  contiguous far sets, yet no greedy chain is r-far. For k = 4, 5 no
  counterexample was found in 31.5 million random cases — this is *not*
  evidence (the tight-pair conjecture survived 55 million random tests before
  being refuted); open.
* **H2u: "the arc property at r = r* suffices for the binary search with the
  closing test."** False: a 6-point set for k = 4 has the arc property at r*,
  but the unchecked test accepts a larger radius. (With pairwise-verified
  chains, H2, the binary search returned r* in all 2.35 million cases.)
* **H3: "some greedy chain is r*-far" (no hypothesis).** False for k >= 4, in
  6-9 % of the (mostly thin) random instances; true for k = 3.
* **P\*** (the 8-point set of the earlier paper, r^2 = 10240, k = 4) violates
  the arc property (beta = 6; Far(p_0) has three runs), is not unimodal, has
  no r-far greedy chain, and the adaptive mode reports `NOT_APPLICABLE`.
* **Using D without the hypothesis** is wrong in a noticeable fraction of the
  (instance, r, k) triples on thin families (see `results/tables.md`), so the
  arc check of the adaptive mode cannot be dropped.

## 6. Results

All numbers below are produced by `./run_all.sh` followed by
`python3 make_tables.py`; the timing runs start only after every correctness
check has passed. Full tables: `results/tables.md`.

* **Correctness:** 2,701 instances with n <= 16 (ten families): 2,648,328
  comparisons of D(r) with exhaustive search at radii where the arc property
  holds, 23,927 optimum checks for O1/O2/adaptive, 176 instances with
  20 <= n <= 150 against the capped Delaunay DP, independent Python brute
  force on 55 exported instances (641 solver values, 23,263 direct checks of
  Theorem A2). **0 failures.**
* **Feasibility of large unimodal inputs:** see D2 and `results/feasibility.txt`.
* **Structure at r\*:** beta = 0 on every hull of a random cloud, every
  cocircular and every jittered-polygon instance; never on thin ellipses and
  two-chain lenses. Greedy chains are r\*-far in all tests with beta <= 2 and
  in 12-58 % of the tests with larger beta.
* **Scaling (unimodal, medians over 3 instances):** O2 solves n = 10^6 in
  about 6 s (128-bit distances); log-log slope 1.15 for n = 10^3..10^6. O1 has
  slope 2.11, the cubic DP 3.16 (n = 100..400). At n = 400, O2 is 300x (k = 4)
  to 40,000x (k = 64) faster than the DP.
