\begin{abstract}
Given $n$ points in $\R^d$ and an integer $k\le n$, the $k$-dispersion
problem asks for $k$ of the points whose minimum pairwise distance is as large
as possible. Chen and Dumitrescu~\cite{CD25} show (Theorem~2) that for
$2\le k\le 8$ the problem can be solved by reducing it to $k$-clique detection
in threshold graphs and then to triangle detection, solved with fast
rectangular matrix multiplication in the style of Ne\v{s}et\v{r}il--Poljak
\cite{NP85} and Eisenbrand--Grandoni \cite{EG04}. This report describes a C++
implementation of that algorithm: the notation, the algorithms, the
implementation choices (exact integer arithmetic, bitset graphs, the
per-$k$ clique split taken from the paper's proof of Theorem~2, and an isolated
matrix-multiplication backend), and a cross-verification against an
independent exhaustive solver on a deterministic dataset of \NumInstances{}
instances drawn from \NumFamilies{} point distributions. The FMM-based solver
returned the same optimum as the exhaustive solver on
\NumOptMatch{}/\NumInstances{} instances, and every returned point set was
independently confirmed to achieve the reported optimum.
\end{abstract}

\section{Introduction}
%======================================================================

The \emph{(max-min) $k$-dispersion problem} asks to place $k$ facilities at
$k$ of $n$ candidate locations so that the facilities are as far apart as
possible, measured by the smallest pairwise distance. It is NP-hard already in
the plane when $k$ is part of the input~\cite{WK88}, so research focuses on
running times of the form $n^{f(k)}$ for fixed $k$.

The paper of Chen and Dumitrescu~\cite{CD25} contributes three kinds of
algorithms:
\begin{enumerate}
  \item a recursive \emph{combinatorial} algorithm running in
        $O(n^{k-1}\log n)$ time in the plane (Theorem~1) and a similar bound
        in $\R^3$ (Theorem~3);
  \item \emph{FMM based} algorithms (Section~3, Theorem~2) that improve the
        earlier bounds of Akagi et al.~\cite{Akagi18} for $k=4,5,7,8$ by
        choosing suitable \emph{rectangular} matrix products;
  \item a linear-time $0.99$-approximation for random points
        (Theorem~4).
\end{enumerate}

\paragraph{Scope of this project.} This project implements the FMM based
algorithm of item~2 (Section~3 / Theorem~2 of~\cite{CD25}), which works for
points in any dimension $d$ and, more generally, for any complete graph with
positive edge weights. We additionally implement an exhaustive solver that is
used purely as a correctness oracle. The combinatorial algorithm $A(k)$ and
the approximation algorithm $B(k)$ are out of scope.

\paragraph{Contributions.}
\begin{itemize}
  \item An exact solver for $k$-dispersion with integer coordinates in any
        dimension, built on the triangle-detection reduction with the
        clique split $(k_1,k_2,k_3)$ prescribed by the proof of Theorem~2.
  \item An instrumented driver reporting binary-search steps, clique-list sizes
        and solve time.
  \item An independent exhaustive oracle, a reproducible dataset of
        \NumInstances{} instances, and a verification harness that checks
        every answer.
\end{itemize}

\section{Background from the paper}
%======================================================================

\subsection{From dispersion to cliques}

\begin{lemma}\label{lem:candidates}
$\mathrm{OPT}\in\mathcal{R}$, i.e.\ the optimum is one of the pairwise
(squared) distances.
\end{lemma}
\begin{proof}
$\delta(S)$ is a minimum over pairs of $S$, hence equals $D(i,j)$ for some
pair; in particular for an optimal $S$.
\end{proof}

\begin{lemma}\label{lem:clique}
For every $r$, there is $S$ with $|S|=k$ and $\delta(S)\ge r$ if and only if
$G_r$ contains a $\Kk$. Moreover, feasibility is monotone: if $G_r$ contains a
$\Kk$ and $r'\le r$, then so does $G_{r'}$.
\end{lemma}
\begin{proof}
$\delta(S)\ge r$ means every pair of $S$ is at squared distance $\ge r$, i.e.\
every pair is an edge of $G_r$. Monotonicity follows from
$E(G_r)\subseteq E(G_{r'})$.
\end{proof}

By Lemmas~\ref{lem:candidates} and~\ref{lem:clique}, $\mathrm{OPT}$ is the
largest $r\in\mathcal{R}$ for which $G_r$ contains a $\Kk$, which can be
found by binary search over $\mathcal{R}$ with
$\lceil\log_2(|\mathcal{R}|+1)\rceil = O(\log n)$ clique tests. This is the
framework of Akagi et al.~\cite{Akagi18}, which~\cite{CD25} builds on.

\subsection{From cliques to triangles}

Let $k=k_1+k_2+k_3$ with $k_i\ge 0$. Build the tripartite auxiliary graph $H$
whose parts are $V_1,V_2,V_3$ (the $k_i$-cliques of $G$), with an edge between
clique-nodes $A\in V_a$ and $B\in V_b$ ($a\ne b$) iff $A\sim B$.

\begin{lemma}[Ne\v{s}et\v{r}il--Poljak~\cite{NP85}]\label{lem:triangle}
$G$ contains a $\Kk$ if and only if $H$ contains a triangle
$(A_1,A_2,A_3)$ with $A_i\in V_i$. In that case $A_1\cup A_2\cup A_3$ is a $\Kk$.
\end{lemma}
\begin{proof}
($\Leftarrow$) Pairwise compatibility means every pair of vertices from
different $A_i$ is an edge; within each $A_i$ every pair is an edge since $A_i$
is a clique. Compatibility forces the $A_i$ to be disjoint (a vertex is not
adjacent to itself), so the union has exactly $k$ vertices.
($\Rightarrow$) Split the vertices of a $\Kk$ into parts of sizes
$k_1,k_2,k_3$.
\end{proof}

A triangle exists iff there are $a,c$ with $M_{13}[a,c]=1$ and
$(M_{12}M_{23})[a,c]>0$. Computing $\Pi=M_{12}M_{23}$ is a product of an
$|V_1|\times|V_2|$ by a $|V_2|\times|V_3|$ matrix, i.e.\ of shape
$n^{k_1}\times n^{k_2}$ by $n^{k_2}\times n^{k_3}$ in the worst case,
which costs $O(n^{\omega(k_1,k_2,k_3)})$ with fast rectangular matrix
multiplication.

\subsection{The splits used in Theorem~2}

Nešetřil and Poljak use the balanced split; the improvement of~\cite{CD25}
comes from using the rectangular product that is cheapest for each $k$,
following Eisenbrand and Grandoni~\cite{EG04}. Table~\ref{tab:split}
reproduces the exponents stated in the proof of Theorem~2 and the
split that realises each one. These are the splits used by our implementation

\section{Algorithms implemented}
%======================================================================

\subsection{Algorithm 1: k-dispersion by binary search}

\begin{algorithm}[H]
\caption{\textsc{Dispersion}$(P,k)$ \quad (\texttt{FMMKDispersion::solve})}
\label{alg:solve}
\begin{algorithmic}[1]
\State compute $D(i,j)$ for all $i<j$ \Comment{exact, 128-bit}
\State $\mathcal{R}\gets$ sorted distinct values of $D$
\State $lo\gets 0$, $hi\gets|\mathcal{R}|-1$, $best\gets\bot$
\While{$lo\le hi$}
  \State $mid\gets\lfloor(lo+hi)/2\rfloor$, $r\gets\mathcal{R}[mid]$
  \State build $G_r$ \Comment{bitset adjacency}
  \State $(found, W)\gets\textsc{FMMClique}(G_r,k)$
  \If{$found$} $best\gets(r,W)$; $lo\gets mid+1$
  \Else\ $hi\gets mid-1$
  \EndIf
\EndWhile
\State \Return $best$ \Comment{$\mathrm{OPT}=r$, $W$ is an optimal $k$-set}
\end{algorithmic}
\end{algorithm}

The smallest value of $\mathcal{R}$ is always feasible ($G_r$ is complete),
so $best\neq\bot$ whenever $n\ge k\ge 2$.

\subsection{Algorithm 2: FMM-based k-clique detection}

\begin{algorithm}[H]
\caption{\textsc{FMMClique}$(G,k)$ \quad (\texttt{FMMKDispersion::fmm\_clique})}
\label{alg:clique}
\begin{algorithmic}[1]
\State $(k_1,k_2,k_3)\gets\textsc{CliqueSplit}(k)$ \Comment{Table~\ref{tab:split}}
\State $V_i\gets\textsc{EnumerateCliques}(G,k_i)$ for $i=1,2,3$
\If{some $V_i=\emptyset$} \Return (\textbf{false}, --) \EndIf
\State $M_{12}[a,b]\gets[V_1[a]\sim V_2[b]]$
\State $M_{23}[b,c]\gets[V_2[b]\sim V_3[c]]$
\State $M_{13}[a,c]\gets[V_1[a]\sim V_3[c]]$
\State $\Pi\gets M_{12}\cdot M_{23}$ \Comment{the matrix multiplication step}
\For{each $(a,c)$ with $M_{13}[a,c]=1$ and $\Pi[a,c]>0$}
  \State find $b$ with $M_{12}[a,b]=M_{23}[b,c]=1$ \Comment{witness recovery}
  \State \Return (\textbf{true}, $V_1[a]\cup V_2[b]\cup V_3[c]$)
\EndFor
\State \Return (\textbf{false}, --)
\end{algorithmic}
\end{algorithm}

Correctness follows from Lemma~\ref{lem:triangle}. Witness recovery scans one
row/column pair, $O(|V_2|)$, once; it is needed only to output the selected
points, not to decide feasibility.

\subsection{Algorithm 3: clique enumeration}

\textsc{EnumerateCliques}$(G,q)$ (\texttt{clique.cpp}) is a depth-first search
that extends a partial clique $C$ only with candidate vertices of larger index
that are adjacent to every vertex of $C$. The candidate list is filtered on
each extension, so every $q$-clique is produced exactly once, in increasing
vertex order. For $q=0$ it returns the single empty clique.

\subsection{Algorithm 4: exhaustive oracle}

\texttt{verify/brute\_force.cpp} enumerates all $\binom nk$ subsets in
lexicographic order and keeps the first one of maximum $\delta(S)$. It reuses
prefix minima $\mathrm{cur}[i]=\delta(\{p_{\mathrm{idx}[0]},\dots,p_{\mathrm{idx}[i]}\})$
so that advancing to the next subset only recomputes the changed suffix.
It shares no code with the FMM solver and runs in $O(\binom nk k^2)$ time,
which is fast enough for the instance sizes used in verification.

\subsection{Design decisions}

\paragraph{Exact arithmetic.} Coordinates are signed 64-bit integers and
squared distances are stored as \texttt{unsigned \_\_int128}. No square roots
or floating point are used anywhere, so ties (common on grids) are resolved
exactly. The result is exact as long as
$d\cdot(2\max|x|)^2<2^{128}$; e.g.\ $|x|<2^{61}$ for $d\le 16$.

\paragraph{Threshold graphs as bitsets.} Row $i$ of the adjacency matrix of
$G_r$ is stored as $\lceil n/64\rceil$ 64-bit words, so each edge query in
clique enumeration and in \texttt{compatible} is a shift and a mask.

\paragraph{Compatibility.} $A\sim B$ is tested by checking all
$|A|\cdot|B|$ cross pairs. Because \texttt{edge(u,u)} is false, overlapping
cliques are automatically incompatible, which enforces disjointness without
an extra test.

\paragraph{Clique split.} \texttt{clique\_split(k)} returns exactly the splits
of Table~\ref{tab:split}. The product computed is $\Pi=M_{12}M_{23}$, so its
shape $|V_1|\times|V_2|$ by $|V_2|\times|V_3|$ matches the rectangular
product $\omega(k_1,k_2,k_3)$ used in the paper's exponent.

\paragraph{Matrix-multiplication backend.} All matrix multiplication goes
through one function, \texttt{multiply\_blocked}: an exact, cache-blocked
($64\times64$ tiles) classical product over 64-bit unsigned integers that
skips zero entries of the left operand. The paper's asymptotic bounds rely on
fast rectangular matrix multiplication algorithms~\cite{EG04,LGU18,VXXZ24},
which have very large constants and are not used in practice; the paper does
not prescribe a concrete implementation. Isolating the product means a fast
algorithm can be substituted without touching the rest of the code.
Entries of $\Pi$ are at most $|V_2|\le\binom{n}{k_2}$, far below $2^{64}$.

\paragraph{Instrumentation.} \texttt{SolveStats} records
$|\mathcal{R}|$, the number of binary-search steps (clique tests), the number of
matrix products, and the largest $|V_1|,|V_2|,|V_3|$ seen. With
\texttt{-{}-stats} the driver prints these together with the split and the
solve time.

\subsection{Complexity of the implementation}

Each clique test costs $O(n^{\max k_i}k)$ for enumeration,
$O(|V_a||V_b|k_ak_b)$ to fill the three matrices, and the product. With the
classical backend the product costs $O(|V_1||V_2||V_3|)=O(n^k)$, so the total is
$O(n^k\log n)$. Replacing \texttt{multiply\_blocked} by a fast rectangular
algorithm gives the $O(n^{e(k)}\log n)$ bound of Table~\ref{tab:split}. The
paper notes that the $\log n$ factor disappears once the exponents are rounded up.
The memory used is dominated by the three matrices,
$O(|V_1||V_2|+|V_2||V_3|+|V_1||V_3|)$ words.

\section{Verification methodology}

\subsection{Approach}

The FMM solver is verified \emph{differentially} against the exhaustive oracle
of Algorithm~4. The two programs share no code (distance computation, search,
and output are written independently) and read the same input files. For every
instance the harness \texttt{verify/run\_verification.py} checks:
\begin{enumerate}
  \item \textbf{Optimum agreement:} both programs report the same
        $\mathrm{OPT}$.
  \item \textbf{Witness validity:} each returned index set has exactly $k$
        distinct indices in $[0,n)$.
  \item \textbf{Witness value:} $\delta(S)$ of each returned set, recomputed in
        Python with arbitrary-precision integers, equals the reported optimum.
        This independently confirms the FMM solver's certificate.
  \item \textbf{Split conformance:} the split reported by the solver equals
        the one in Table~\ref{tab:split}.
\end{enumerate}
Whether the two programs return the \emph{same} set is also recorded. This is
informational only, since optimal sets need not be unique.

        (coincident, collinear, tied, near-equal and very large values).
  \item The number of clique tests is $\lceil\log_2(|\mathcal{R}|+1)\rceil$ or one
        less, as expected from binary search. It is about 5--10 even for
        $|\mathcal{R}|$ in the hundreds.
  \item The largest clique lists occur for the largest part, e.g.\
        $\binom{16}{4}=1820$ $4$-cliques for $k=8$ with split $(2,2,4)$. This
        shows how the split determines the matrix shapes.
\end{itemize}

\paragraph{Discussion.} With the classical backend the FMM-based solver is
\emph{not} faster than exhaustive search at these sizes, and for $k=6$ it is
several times slower. This is consistent with the analysis: each clique test
performs about $|V_1||V_2||V_3|\approx n^k/(k_1!\,k_2!\,k_3!)$ operations, and there are
$\Theta(\log n)$ tests. Exhaustive search performs about $n^k/k!$ subset
steps. For $k=6$, $k_1!k_2!k_3!=8$ while $k!=720$. The asymptotic gain of
Theorem~2 comes entirely from replacing the classical product with fast
rectangular matrix multiplication. The paper itself notes that FMM-based
algorithms are generally considered impractical because of their large
constants, and that it is unclear from which $k$ they win in practice. The
experiments confirm that the reduction is \emph{correct}; demonstrating its
\emph{speed} would need a fast multiplication backend and much larger inputs.

%======================================================================
\section{Limitations and future work}
%======================================================================

\begin{itemize}
  \item \textbf{Fast matrix multiplication.} The backend is classical; plugging
        in Strassen-like or rectangular algorithms, or a bit-packed Boolean
        product (only $\Pi[a,c]>0$ is needed), is the natural next step.
  \item \textbf{Memory.} $M_{13}$ and $M_{23}$ have up to
        $\binom n{k_2}\binom n{k_3}$ entries stored as 64-bit words;
        bit-packing would cut memory by $64\times$.
  \item \textbf{Other algorithms of the paper.} The combinatorial algorithm
        $A(k)$ of Theorems~1 and~3 ($O(n^{k-1}\log n)$ in the plane) and the
        approximation algorithm $B(k)$ of Theorem~4 are not implemented.
  \item \textbf{Input range.} Exactness requires $d(2\max|x|)^2<2^{128}$, see
        Section~5.2.
\end{itemize}

%======================================================================
\section{Conclusion}
%======================================================================

We implemented the FMM based exact algorithm for $k$-dispersion from Section~3
of Chen and Dumitrescu~\cite{CD25}: binary search over pairwise distances,
reduction of each decision problem to $k$-clique detection in a threshold
graph, and reduction of $k$-clique detection to triangle detection via a single
matrix product with the clique split $(k_1,k_2,k_3)$ prescribed by the proof of
Theorem~2. A differential test against an independent exhaustive solver on
\NumInstances{} instances from \NumFamilies{} families (including degenerate
inputs) found no discrepancy, and every returned solution was independently
certified. The running-time experiments show that, as the authors anticipate,
the asymptotic advantage depends on fast matrix multiplication and does not
appear with a classical backend at practical sizes.
